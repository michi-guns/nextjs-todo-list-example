# Source Guide — Page Flows

Website: https://pageflows.com/

## Role

Use Page Flows when the design problem is fundamentally about a journey rather than a single static screen.

Strong use cases include:

- onboarding
- signup/login/recovery
- checkout and payment
- upgrade/subscription flows
- search and discovery
- adding/creating/editing content
- invitations/sharing
- destructive actions and confirmation
- guided tours
- multi-step settings or configuration

Page Flows is valuable because screen recordings and sequential examples can reveal interaction order, transitions, decision points, and state changes that a single screenshot hides.

## Best use

Ask:

- What does the user see before this screen?
- What decision happens here?
- What feedback confirms progress?
- What state appears after success/failure?
- Which information is deferred until needed?

Use those observations to influence workflow hypotheses.

## Access

Use browser/web access when available. Some content may require authentication or a subscription. Do not block the exploration if full flows are unavailable.

Do not encode current prices or plan details in the skill.

## Avoid

- using flow evidence to justify copying exact visuals
- judging a flow only from its first screen
- ignoring product differences such as risk, compliance, or user expertise
