# Source Guide — Mobbin

Website: https://mobbin.com/

## Role

Use Mobbin primarily as evidence for real shipped product UI and established interaction patterns.

It is especially useful when the problem involves:

- mobile or responsive product screens
- onboarding and activation
- account/settings
- navigation
- commerce and payments
- search/filtering
- common product states

## Best use

Search by user task, flow, or screen purpose rather than by visual style.

Prefer queries conceptually like:

- transaction history filtering
- identity verification onboarding
- device setup
- subscription management
- refund flow

Extract the pattern and its purpose, for example:

> High-frequency financial apps keep filter state visible while preserving a stable scan path through records.

Do not reduce the observation to:

> Copy this screen.

## Access

If a Mobbin MCP/native integration is configured, prefer it for structured agent research. Otherwise use accessible browser/web search. If neither is available, skip Mobbin without blocking the exploration.

Do not assume subscription status, current plan names, or installation syntax. Check current Mobbin documentation if setup details matter.

## What to record

For each relevant reference:

- product/surface
- user problem
- observed pattern
- why it applies to this project
- transferable principle
- aspect not to copy
- retrievable URL/source identifier if available

## Avoid

- choosing a direction because the source product is famous
- cloning one product's composition
- treating a screenshot as proof that a workflow is good
- using marketing/landing-page patterns for dense operational interfaces without justification
