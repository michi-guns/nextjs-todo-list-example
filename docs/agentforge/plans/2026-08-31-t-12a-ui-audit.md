## Constraints and scope

- Keep the existing landing, auth, and dashboard routes, action/route adapters,
  view models, and Focus Rail hierarchy intact.
- Use existing semantic Tailwind/shadcn tokens and composable primitives; do
  not introduce a new design system, navigation model, or domain layer.
- Do not change persistence, authentication configuration, Sanity behavior, or
  business rules.
- Browser/runtime inspection is required because this task owns materialized UI
  evidence; full deterministic authenticated and mailbox journeys remain
  T-15-owned.

## Evidence-backed findings and bounded changes

1. The public/auth header and authenticated dashboard rail contain persistent
   navigation/context, but keyboard users have no skip-to-content link. Add one
   shared, focus-visible `SkipLink` primitive and place it before the relevant
   shell content, targeting the landing/auth content region and dashboard main
   region. Give the targets stable IDs and preserve visible focus styling.
2. The landing preview is intentionally decorative (`aria-hidden` descendants)
   while its wrapper is exposed as a labelled complementary landmark. Hide the
   wrapper from the accessibility tree so it does not announce an empty region;
   keep the visual preview unchanged.
3. Re-run the four-viewport browser audit and state checks after the corrections.
   Do not add speculative changes when the existing hierarchy, labels, focus,
   responsive wrapping, loading/error/empty states, and token usage satisfy the
   handoff.
