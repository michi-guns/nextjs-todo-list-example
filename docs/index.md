## Build or change a feature

1. Read this index and the documentation protocol.
2. Read the relevant architecture, domain, and data documents.
3. Read the product documents and linked ADRs.
4. Check active assumptions and open questions.
5. Follow the implementation workflow and quality gates.

## Document map

- `handbook/`: fast human orientation
- `architecture/`: application boundaries and dependency rules
- `domain/`: business concepts, rules, lifecycles, and uncertainty
- `data/`: ownership and consistency rules
- `development/`: implementation and agent guidance
- `adr/`: historical architectural decisions
- `runbooks/`: operational recovery procedures
- `product/`: requirements and build contract

When documents disagree, follow [the documentation protocol](./documentation-protocol.md).
